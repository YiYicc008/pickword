# 拾词 · 电子英语单词本

**拾词（Pickword）—— 一个可以在 Windows 电脑 / iPad / 鸿蒙手机上使用的电子英语单词本。**

> 名字的来历：遇见一个词，**拾**起来放进本子；再遇见一次，它在那个本子里的权重就 +1。
纯前端 PWA，零依赖、零构建：双击就能跑，也可以放到任意静态网站空间，用浏览器「添加到主屏幕」后像 App 一样使用。

录入单词会自动补上音标、发音、词性和中文释义；每个单词带一个看得见的**权重**；
一个单词本既能按权重/时间排序，也能摊成一张可交互的**词云**（节点=单词，词团=变体/同义/反义/形近，多个词团组成词云）。

## 功能一览

| 能力 | 说明 |
| --- | --- |
| 多单词本 | 自己命名、挑颜色，各自独立计数 |
| 录入单词 | 手动勾选放进哪几个本；也可以点「AI 智能分类」让它判断 |
| 自动补全 | 音标、发音、词性、多义项中文；可配 AI 提升中文质量 |
| 权重 | 首次加入 = 1，同一单词再进同一本 +1，直接显示在单词旁 |
| 排序 | 权重升/降序、加入时间升/降序 |
| 词云 | 自研力导向图，词团可部分重叠但视觉可辨；AI 可一键生成词团与词云 |
| 编辑 | 详情里拖动排序释义卡片、改词性/中文、加自定义释义 |
| 三端 | 同一个网页适配桌面 / 平板 / 手机，可「添加到主屏幕」离线使用 |
| 同步 | 可选 Supabase：邮箱登录，三端共享同一份数据 |

> **在线试用**：<https://YiYicc008.github.io/pickword/index.html?demo>（`?demo` 会载入示例数据）
> 自己怎么用起来有三种方式（现成网址 / 本机小服务器 / 部署成自己的网站），见「一、先选一种用法」。

界面语言：简体中文　｜　代码：原生 JavaScript（ES Modules），零依赖、无构建步骤

## 一、先选一种用法

拾词有三种用起来的方式，**按你的需要挑一个就行**，不用全都做：

| 用法 | 适合谁 | 怎么开始 |
| --- | --- | --- |
| **① 直接用现成的网址** | 只想用，不想装任何东西 | 打开 `https://YiYicc008.github.io/pickword/`（示例数据：`…/index.html?demo`） |
| **② 在自己电脑上跑** | 想完全离线、数据只留在本机 | 双击 `start.bat`，手机连同一个 WiFi 访问 |
| **③ 部署成自己的网站** | 想拥有自己的地址、三端随时访问 | 见下面第 3 小节 |

下面三小节依次讲：**① 直接访问**、**② 在本机跑一个小服务器**、**③ 部署成自己的网站**。

### 1. 用法 ①：直接用现成的网址（最快，什么都不用装）

1. 电脑 / iPad / 手机浏览器打开 `https://YiYicc008.github.io/pickword/`
2. 想先看效果就加 `?demo`：`https://YiYicc008.github.io/pickword/index.html?demo`
3. 收进主屏幕（见下面第 4 小节）之后，断网也能用

> 三端要**共享同一份单词本**，还需要配一次云同步（第四节）。
> 不配的话每台设备各自存各的，但都能正常用。

### 2. 用法 ②：在自己电脑上跑（局域网，不需要公网）

双击 **`start.bat`**。

脚本会：

1. 启动一个本地服务（默认 `http://127.0.0.1:8080`）；
2. 自动用默认浏览器打开页面；
3. 在控制台列出**手机 / 平板可以访问的局域网地址**，例如：

```
==============================================================
  拾词 · 电子英语单词本
==============================================================

  本机访问（这台电脑）：http://127.0.0.1:8080/index.html
  同一 WiFi 下的手机 / 平板访问：
      http://192.168.1.7:8080/index.html

  按 Ctrl+C 停止服务。
==============================================================
```

> **要一直开着这个黑色窗口**，它就是服务器；关掉窗口页面就打不开了（重新双击 `start.bat` 即可）。
> 8080 端口被别的程序占用时，脚本会自动顺延到 8081 / 8082 …，以窗口里打印的地址为准。
>
> 需要电脑装有 Python 3。没有的话到 <https://www.python.org/downloads/> 安装，
> 安装时勾选 *Add python.exe to PATH*。也可以把整个文件夹丢到任意静态服务器上。

### 3. 用法 ③：部署成自己的网站（GitHub Pages）

把整个文件夹发布到 GitHub Pages，得到自己的公网地址（本项目在用的就是
`https://YiYicc008.github.io/pickword/`）。部署之后**三端不再需要同一个 WiFi**：任何网络都能打开，
装到主屏幕后离线也能用（数据要三端共享，还要接着配第四节云同步）。

1. 在 GitHub 新建一个仓库，把整个文件夹推上去：

   ```bash
   git init
   git add .
   git commit -m "init: 拾词 · 电子英语单词本"
   git branch -M main
   git remote add origin https://github.com/YiYicc008/pickword.git
   git push -u origin main
   ```

2. 仓库 **Settings → Pages**：Source 选 `Deploy from a branch`，Branch 选 `main`、目录 `/(root)`，Save。

3. 等一两分钟，访问 `https://YiYicc008.github.io/pickword/`。
   想直接看示例数据就加 `?demo`：`…/index.html?demo`。

4. 收进主屏幕见下面第 4 小节。

**谁打开这个网址？看到的是谁的数据？**

- 公开仓库的 Pages 是公开的：拿到链接的人都能打开页面，不需要登录。
- 但每个人打开的是**他自己的**空单词本 —— 数据存在各自浏览器的 `localStorage` 里，互相看不到。
  `?demo` 只是往**他自己**的浏览器里灌一份示例数据，不影响作者的数据。
- 谁想同步，注册的是**他自己的** Supabase 账号（第四节），按 RLS 只能读写自己那一行。
- 私有仓库要用 Pages 需要 GitHub Pro；公开仓库免费。

几点说明：

- 所有资源都用相对路径，放在子目录（`https://…/pickword/`）也能正常工作；
- 根目录的 `.nojekyll` 用来跳过 Jekyll 处理，避免带下划线/特殊名字的文件被忽略；
- 换成 Netlify / Vercel / Cloudflare Pages 也一样，都是纯静态托管，直接把文件夹拖进去即可；
- 只想局域网用，就不必做这一步，按「用法 ②」双击 `start.bat` 就行。

### 4. 收进主屏幕（三种用法都适用）

手机 / 平板打开地址后：

- **用法 ①**：直接用 `https://YiYicc008.github.io/pickword/`，任何网络都行；
- **用法 ②**：让设备连上**和电脑同一个 WiFi**，打开 start.bat 窗口里列出的局域网地址（如 `http://192.168.1.7:8080/index.html`）；
- **用法 ③**：部署完就是用法 ① 那个地址，同样打开即可。

然后收进主屏幕，之后就像 App 一样点开：

- **iPad（Safari）**：分享 → 添加到主屏幕
- **鸿蒙 / 安卓（浏览器）**：菜单 → 添加到桌面
- **Windows（Chrome / Edge）**：地址栏右侧的"安装"图标

三端界面会自动适配：桌面是左右分栏，手机是抽屉式侧栏 + 单列卡片，词云会切换成紧凑模式。

### 5. 想先看看效果

在地址后面加 `?demo`，例如 `https://YiYicc008.github.io/pickword/index.html?demo`（本机则是 `http://127.0.0.1:8080/index.html?demo`），
会载入两个示例单词本（雅思高频词 30 个 / 形近词辨析 8 个）、9 个词团、3 个词云。
换一台设备或清空数据后不会重复写入，只有"只有一个空单词本"时才会填充。

## 二、功能说明

### 单词本

- 左侧（手机上在抽屉里）列出一个或多个单词本，每个可以**自定义命名、选颜色**；
- 侧栏里点 `+` 新建；右键单词本可重命名 / 清空 / 删除；
- 顶部标题旁的铅笔也能直接改名。

### 录入单词

点右上角 **添加单词**（桌面快捷键 `n`）：

- 一次可以录多个，用**逗号或换行**分隔；
- 用圆点标签选择要放进哪些单词本，**可多选**；单词会同时进入每个选中的单词本，各自独立计数；
- 点 **AI 智能分类**：由 AI 判断该词属于哪些单词本，并自动勾选（选中的会带 `AI` 角标）；
- 录入时自动补全**音标、词性、多义项中文释义、发音音频**：
  - 音标/词性/发音来自免费词典 API（<https://dictionaryapi.dev>，需要联网，结果本地缓存 30 天）；
    音标取同一词条里出现次数最多的写法（`/ɹʌn/` 这类生僻 IPA 字母会转成 `r` 等常见写法，避免字体显示不出来）；
  - **一个词有多个意思时，按词性各列一条**（最多 4 条）：`v. 快速移动` / `n. 跑步的行为或例子`，
    列表里显示前两条（中文重复的会合并，末尾提示「还有 N 个义项」），详情弹窗里显示全部（含英文释义和例句）；
  - 词性按「该词性下的释义条数」排序，主词性排在最前面（词典接口本身的顺序是乱的，
    例如 happy 会把罕用的名词排第一、big 会把名词和动词排第一，这里已经纠正）；
  - 中文释义优先用 AI 逐条翻译（更短更准），没配 AI 时逐条翻译英文释义再压成短句；
  - **常见的意思排在前面**：每个词另有一行「常见释义」（见详情里带橙底的「常见」行），
    来自整词的高频译法，按常用度排序（`sad` 会显示「悲伤的」，不会把古义「吃饱了」「阿拉伯字母萨德」顶到前面）；
    只有当词典义项和这行常见释义对得上时，列表才按词性逐条展开，否则只显示常见释义；
  - 词典里那些和常见释义对不上的古义/罕用义项，在详情里会淡化并标上「冷僻」；
  - 词典接口偶尔会限流/失败，这时单词会先加进来、释义留空，工具栏会出现 **补全释义 N** 按钮，
    点一下就能把缺音标/缺释义的词重新查一遍（详情里的 **重新获取** 按钮同理）。

### 全部重新获取

工具栏右侧的 **全部重新获取** 会把**当前单词本里所有单词**的音标、发音、词性和释义重查一遍：

- 适合「当时接口抽风、很多词释义不对/为空，现在想整体刷一遍」；
- 词典接口有限速，会一个个查（每个之间隔 0.4 秒），30 个词大约半分钟到一分钟；
- 过程中单词会**逐个更新**，按钮变成 `取消 · 12/30`，随时可以点它停下；
- **只覆盖查回来的内容**：查不到的词保留原来的释义，不会变空；
- **手动编辑过的单词默认不会被覆盖**：点「全部重新获取」会先弹提示框，里面有一项
  「覆盖手动编辑过的 N 个单词」；勾上它再点「开始」，会列出这些被你改过释义的单词（带全选按钮），
  只覆盖你勾选的那几个（「全选」「清空」是两个独立按钮），没勾的只更新音标和发音、释义保持你写的；
  不勾就直接开始，等于全部保留。
  详情里的 **重新获取** 也是同一套提示（只是针对当前这一个词）。
- 免费翻译接口（MyMemory）每天有额度，短时间内刷太多会报 `429`。这时程序会自动停下并提示
  「翻译接口限流」，已处理的词照常保存，剩下的过一阵再点一次即可；同一个词的结果会整词缓存，
  重复刷新不会重复消耗额度。
- 想一次到位、不受额度影响：在 **设置 → AI 服务** 填一个 DeepSeek / OpenAI 的 Key，
  义项翻译会明显更准更短（Key 只存在本机浏览器里）。

### 编辑释义（拖动排序、自定义词性与中文）

点开任意单词的详情，最上面的卡片就是它的释义，可以直接改：

- **改词性**：点左侧的 `v.` / `n.` / `adj.` 小框，手输缩写或中文都行（`v.`、`verb`、动词、短语……），保存时会归一成同一种标签；
- **改中文**：点后面的中文直接编辑；
- **拖动排序**：按住卡片（输入框和按钮以外的位置，左侧 `⋮⋮` 手柄也可以）上下拖，
  卡片会「浮」起来跟着鼠标走，原位留一个虚线占位框告诉你松手后会落在哪；
  松手时卡片会滑回那个位置（约 0.19 秒的过渡），保存后列表里按这个顺序显示。
  触屏（iPad / 手机）上为了不和页面滚动打架，请**按住左侧 `⋮⋮` 手柄**再拖；
- **添加释义**：卡片区最下面是虚线框「+ 添加释义」，点一下多出一张空卡片，填上词性和中文即可（适合补充习语、专有含义）；
- **删除**：卡片右侧的 `×`；
- 第一张卡片会标「常用」，和它意思对不上的会标「冷僻」并淡化，一眼能看出哪个是生僻义；
- 列表里每个单词只显示排在前面的两条释义，其余在详情里。

**什么才算「手动编辑」**：程序会记住词典/AI 最近一次给出的义项及其顺序，作为「原始基线」。
保存时只有内容**和基线不一样**才算手动编辑 —— 所以你拖乱之后又拖回原样、加了卡片又删掉、改了又改回去，
都不会留下标记，之后「重新获取」也不会再问你要不要覆盖。
（词典还没查成功、没有基线的老词条，标记只增不减，避免误清。）

保存后，如果确实和基线不一样，这个单词就会打上「手动编辑」标记，**列表按你排的顺序显示**（不再按词典的顺序判断）。
之后点「重新获取」或「全部重新获取」时，程序会先问你要不要覆盖这些手动编辑：默认保留（只刷新音标和发音）；
想覆盖就勾上选项，再在弹出的列表里勾选要覆盖的具体单词（有全选按钮）。

### 权重

- 单词第一次进入某个单词本时，权重为 **1**；
- 同一个单词再次进入**同一个**单词本，权重 **+1**；
- 权重直接显示在每个单词右侧的圆形徽标里（列表里是数字，词云里是节点大小 + 右上角角标 + 圆形大小）；
- 单词行悬停会出现 `+` / `−` 按钮，单词详情里也能手动调整；
- 顶部会显示"总权重"和"最高"。

### 两种呈现方式

顶部右侧的 **列表 / 词云** 切换：

1. **列表**——按加入时间或权重排序，升序降序都行（下拉框四项：
   权重 高→低、权重 低→高、时间 新→旧、时间 旧→新），支持搜索英文或中文释义。
2. **词云**——每个单词是一个圆形节点，节点之间有连线，关系越近离得越近：
   - **词团**（cluster）：一组相关单词，用同一色调的半透明轮廓圈出来，
     例如"run 的变式""happy 家族""大小与反义"；
   - **词云**（cloud）：多个词团的集合，一个单词本里可以有多个词云，顶部胶囊按钮切换；
   - **词团可以重叠**：一个单词属于两个词团时，节点的**彩色圆环会分段**显示两种颜色，
     词团轮廓也会互相交叠但不合并，视觉上仍能分辨归属；
   - 关系类型用线型区分：变式（实线蓝）、同义词（实线绿）、反义词（虚线红）、形近词（点线橙）；
   - 点击节点看详情（音标、释义、所属词团、权重 +1 / −1、移出本词本）；
   - 拖拽平移、滚轮/双指缩放、`适应` 按钮回到全览；点图例可临时隐藏某个词团。

### 整理词团 / AI 生成关联

词云视图右上角：

- **整理词团**：按已有关系自动聚类成词团（变式归一族、同义/反义/形近各成一团），可反复执行；
- **AI 生成词云**：把整个单词本交给 AI，让它**自己决定怎么分组**——从同义、反义、形近、同词根、
  同主题等角度归纳出若干个词团，再组织成一到三个词云（手动词团会保留）；
- **AI 生成关联**：让 AI 判断词与词两两之间的关系（变式/同义/反义/形近），画出连线并重新聚类；
- **词团 / 词云**：手动管理——新建、改名、改颜色、勾选成员、删除，也能把词团归属到某个词云。

## 三、配置 AI（可选，但强烈建议）

`设置` → **AI 服务**：

| 项目 | 说明 |
| --- | --- |
| 服务 | DeepSeek / OpenAI / Moonshot / 自定义（任意 OpenAI 兼容接口） |
| 接口地址 | 默认已填好，例如 `https://api.deepseek.com/v1` |
| 模型 | 例如 `deepseek-chat`、`gpt-4o-mini` |
| API Key | 只保存在本机浏览器（localStorage），不会上传到任何第三方 |

填好后点 **测试连接**。AI 会被用于三件事：录入时的**智能分类**、缺释义时的**中文翻译**、词云里的**关系生成**。
不配 AI 也能用，只是这三项需要手动。

## 四、多端同步（可选）

**这一步只解决"三端看到同一份数据"。** 不配也能用，只是每台设备各自存各的（浏览器 `localStorage`）。
同步用 [Supabase](https://supabase.com) 免费版就够：一个账号、一张表、邮箱密码登录，数据存在你自己的项目里。

### 1. 建一个 Supabase 项目（约 3 分钟）

1. 打开 <https://supabase.com> → `Start your project`，用 GitHub 或邮箱注册（免费计划足够）；
2. `New project`：填项目名（例如 `pickword`）、设置**数据库密码**（自己记好，一般用不到）、
   区域选离你近的（如 `Singapore` / `Tokyo`）→ `Create new project`，等 1–2 分钟初始化完成。

### 2. 拿到两个值

进入项目后点左侧 **Project Settings → API**（新版在 `Data API` / `API Keys`），复制：

| 名称 | 形如 | 用途 |
| --- | --- | --- |
| **Project URL** | `https://abcdefgh.supabase.co` | 数据地址 |
| **anon public key** | `eyJhbGciOi…`（很长） | 匿名公开密钥，可放在前端 |

> `service_role` key **不要**填进来，它绕过所有安全策略，泄露等于把数据库交出去。
> anon key 本身是公开的，安全性靠第 3 步的行级安全（RLS）保证，不是靠藏这个 key。

### 3. 建表（只做一次）

1. 左侧 **SQL Editor** → `New query`；
2. 把 [`supabase/schema.sql`](supabase/schema.sql) 的全部内容粘进去 → **Run**；
3. 看到 `Success. No rows returned` 就好。它做三件事：
   建 `public.vn_state` 表（`user_id` / `data jsonb` / `updated_at`）、打开 RLS、加策略
   `using (auth.uid() = user_id)` —— **每个账号只能读写自己那一行**。

想确认：左侧 **Table Editor** 里能看到 `vn_state`，且右上角写着 `RLS enabled`。

### 4. 账号设置

左侧 **Authentication → Providers → Email**：默认是开的。
默认 `Confirm email` 也开着——注册后要**点邮件里的链接**才能登录。
自己用不想来回收邮件，可以关掉 `Confirm email`（Authentication → Providers → Email → 取消勾选），注册后直接能登录。

### 5. 在应用里填配置

应用 → **设置 → 云同步**：

1. 第 1 段把 **Project URL** 和 **anon public key** 填进去，点 **保存配置**；
2. 第 2 段填邮箱 + 密码（至少 6 位），点 **注册新账号**；若开了邮件确认，先去邮箱点链接；
3. 点 **登录**，成功后这一段会显示当前账号与上次同步时间。

（配置和 AI Key 一样只存在本机浏览器，会随同步一起写进云端，换设备登录后不用重填。）

### 6. 三端同步

在 Windows 上登录后点 **立即同步**，这一台的数据就上云了；
iPad、鸿蒙手机打开同一个网址 → 设置 → 云同步 → 填同样的 URL/key → 登录同一个账号 → **立即同步**。

同步逻辑：**先拉云端 → 与本机合并 → 再上传**。合并规则是按 `单词本 id + 单词 id` 对齐，
同一个单词在两台设备上权重不同时**取较大的那个**（不会因为同步而"掉权重"），关系和词团也按 id 合并。

| 按钮 | 行为 | 什么时候用 |
| --- | --- | --- |
| 立即同步 | 拉取 + 合并 + 上传 | 日常，三端各点一次即可 |
| 从云端恢复 | 用云端数据**完整覆盖本机** | 这一台误删/换设备要拿云端为准 |
| 上传本机 | 用本机数据**覆盖云端** | 云端乱了、本机才是对的 |

### 常见问题

**填好点登录，提示 `Invalid login credentials`？**
账号没注册成功（多半是没点邮件里的确认链接），或密码不对。可以重新点「注册新账号」再试。

**提示"云端的 vn_state 数据表还没有创建"？**
第 3 步的 SQL 没跑成功。回 SQL Editor 重跑一遍 `supabase/schema.sql`。

**登录成功但同步报 401 / 权限错误？**
多半是策略缺了。SQL Editor 里执行 `alter table public.vn_state enable row level security;`
再确认策略存在：`select * from pg_policies where tablename = 'vn_state';`

**免费额度够用吗？**
够。免费计划每月 500 MB 数据库 + 5 GB 出网；整个单词本同步一次只有几十到几百 KB。

**会不会把我的单词看到别人的？**
不会。表开了 RLS，策略是 `auth.uid() = user_id`，数据库层面就拒绝跨账号读；
你的数据在**你自己的** Supabase 项目里，不是存在我或作者那里。

## 六、备份与回滚

数据层面有两条退路：`设置 → 数据 → 导出备份`（生成 JSON），以及第四节的云同步。
代码层面就是普通的 git 仓库：

```bash
git log --oneline          # 看历史
git diff HEAD~1            # 看上次改了什么
git checkout -- .          # 丢弃未提交的改动
git revert <commit>        # 撤销某次提交
```

> 开发期间我还用一个本地脚本 `_snapshot.py` 把工作副本打包成 zip（跳过 `.git`、`_backups`），
> 它和 `_backups/` 都在 `.gitignore` 里，仓库里不包含。

## 七、常见问题

**点喇叭没有声音？**
发音用浏览器自带的语音合成或词典音频。iPad 需要先在系统设置里允许 Safari 播放声音；
台式机没装英文语音包时，会退回到词典音频。

**手机上打不开电脑的地址？**
确认两台设备在同一个 WiFi；Windows 防火墙第一次会弹窗，选"允许访问"。
也可以把整个文件夹部署到 Netlify / Vercel / Cloudflare Pages（都是拖拽上传，免费），
那样三端用同一个 https 地址，离线缓存也能生效。

**添加到主屏幕后是白屏？**
首次打开需要先正常加载一次（Service Worker 要注册成功）。用 `http://` 局域网地址时，
部分浏览器只在 https 或 localhost 下启用离线缓存，但正常使用不受影响。

**换设备后数据没了？**
数据默认只在本机。请先配置"云同步"并同步一次，或导出 JSON 再导入。

**想清空重来？**
`设置 → 数据 → 清空` 会删除所有单词本与词条；只想清一个本，右键该单词本选择"清空"。

## 八、数据与隐私

- 默认**纯本地**：单词本、词条、权重、词团都存在本机浏览器的 `localStorage`（键 `vn.state.v2`），不上传任何服务器；
- AI Key、Supabase 配置同样只存本机，不会写进代码或仓库（仓库里只有占位提示文字）；
- 只有你自己在设置里填了 Supabase 并登录，数据才会同步到**你自己的** Supabase 项目；
  建表 SQL 见 [`supabase/schema.sql`](supabase/schema.sql)，每行数据都有行级安全策略，只有本人可读写；
- 换设备 / 清浏览器缓存前：先「导出 JSON」备份，或先配好云同步并同步一次。

## 九、参与贡献

Issue / PR 都欢迎。动手前请留意三条约定：

- **零依赖、无构建**：不引入 npm 包或编译步骤，保持在浏览器里直接跑的原生 ES Modules；
- **数据向后兼容**：`store.js` 的 state 带 `version` 字段，新增字段要保证老数据能读（缺字段用默认值兜底）；
- **自查**：`python serve.py` 后用 `index.html?demo` 过一遍列表 / 词云 / 详情 / 设置，桌面和 390 宽各看一次。

调试用的 URL 参数（只在 `?demo` 下开放）：

| 参数 | 作用 |
| --- | --- |
| `?demo` | 载入示例数据（两个单词本 38 个词、9 个词团、3 个词云） |
| `?demo&view=cloud` | 直接打开词云视图 |
| `?demo&modal=add` | 直接打开「添加单词」 |
| `?demo&modal=settings` / `sync` / `about` | 直接打开设置 / 云同步 / 关于 |
| `?demo&modal=manager` | 直接打开「词团与词云」管理器 |
